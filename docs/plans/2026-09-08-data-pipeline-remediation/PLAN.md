# Data-pipeline remediation — master plan

> Источник: `docs/reports/data-pipeline-audit-2026-09-08.html` (+ `.json` сайдкар с сырыми
> выборками). Каждая задача этого плана — строка борда из аудита, проработанная до пакета,
> который исполняющий агент может взять без доступа к этой сессии. Контракт: **пакет несёт
> receipts (`file:line`, измеренные числа), TDD-порядок, наблюдаемость, гейты и rollback**.

## Цель

Конвейер данных (repo-индексация, DB-индексация, code↔DB-карта, эмбеддинги, расписание)
становится: (1) **честным** — карта не содержит фантомов, статусы не противоречат сами
себе; (2) **дешёвым** — force_full не платит LLM за неизменившиеся документы; (3)
**наблюдаемым** — деградация и приближение к потолкам видны до отказа; (4)
**доказуемо эксклюзивным** — двойной прогон невозможен между процессами.

## Правила исполнения (обязательны для каждого пакета)

1. **TDD**: тесты из секции «Тесты» пакета пишутся первыми и должны упасть до реализации.
2. **Гейты** — локально до PR: см. `CONVENTIONS.md` § Гейты. Без зелёного — не done.
3. **Наблюдаемость — часть задачи, не follow-up**: логи/счётчики из секции пакета входят
   в тот же PR.
4. **Документы в том же изменении**: `CLAUDE.md`/`API.md`/`docs/ux/scenarios.md` — если
   пакет их называет. Плюс строка в леджере ниже.
5. **Один PR на задачу** (T-xx), squash-merge, заголовок `<type>(scope): …` + `(T-xx)` в
   теле. Ветка `feat/T0x-slug` или `fix/T0x-slug`.
6. Ловушки репозитория, о которые уже спотыкались, собраны в `CONVENTIONS.md` § Ловушки —
   читать до первого коммита.
